# /com-client-switch — COM-клиент 1С по версии платформы

Все версии 8.5 используют **один и тот же CLSID** коннектора, поэтому обслуживать `V85.COMConnector`
может только одна из них — последняя зарегистрировавшая. Навык переключает её на нужную версию
из уже установленных и проверяет, что переключение действительно применилось.

## Usage

```
/com-client-switch list                                  — какие клиенты стоят, какой зарегистрирован
/com-client-switch state                                 — полная картина: CLSID, DLL, типелиб, процессы
/com-client-switch switch  -Version 8.5.1.1529           — переставить регистрацию на эту версию
/com-client-switch restore -FromFile <снимок.json>       — откат по снимку, созданному switch
/com-client-switch check   [database]                    — проба Connect + расшифровка ошибки
```

`check` без базы проверяет только загружаемый DLL.

## Команда

```powershell
powershell.exe -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/com-client.ps1" -Command <команда> <параметры>
```

Параметры: `-Version` (для switch), `-FromFile` (для restore), `-Root` (корень платформы,
по умолчанию `C:\Program Files\1cv8`), `-ProgId` (по умолчанию `V85.COMConnector`; для 8.3 —
`V83.COMConnector`), `-NoApplication` (не трогать `V85.Application`/`V85C.Application`),
`-SnapshotFile`, а для check — `-InfoBaseRef`|`-Server`+`-Ref`|`-UserName`+`-Password`.

## Порядок работы

1. `list` — убедись, что целевая версия есть на диске и `comcntr.dll` в её `bin` цел.
2. Предупреди, что переключение **машинное** и требует админских прав: пишет в `HKLM\SOFTWARE\Classes`,
   затронет все процессы, которые поднимут COM после переключения. Спрашивай подтверждение.
3. `switch -Version <v>` — сам снимет снимок регистрации, сделает `regsvr32` и `/regserver`,
   сама сверит результат и вернёт ненулевой exit при расхождении.
4. `state` — покажи итог. Сравни версию в строке «Загружаемый DLL в свежем процессе» с целью.
5. Если нужны базы другой версии сервера — `check -InfoBaseRef <id>` покажет, какие отвалились.

Откат: `restore -FromFile <снимок>` — путь снимка напечатан в выводе `switch`.

## Что нужно знать, чтобы не сломать

- **`regsvr32` запускать только с рабочей папкой = `bin` этой платформы.** Иначе `exit=3` —
  DLL не находит свои зависимости. Навык это делает сам (`Start-Process -WorkingDirectory`).
- **Никогда не вызывай `DllRegisterServer`/`DllInstall` через P/Invoke.** Возвращает `0x00000000`,
  но при этом сносит `CLSID` коннектора и типелиб, не зарегистрировав замену. Коннектор
  становится недоступен целиком, восстановить можно только повторным `regsvr32` из `bin`.
- **Перенаправление в `HKCU\Software\Classes\CLSID\{...}` не работает** для этого CLSID — HKLM побеждает.
  Поэтому «посадить один процесс на другую версию» нельзя, только машинное переключение.
- **Версионные гейты точные до последнего числа и срабатывают раньше** проверки существования базы
  и аутентификации. Значит «Несоответствие версий (клиент — сервер)» — это не поломанная регистрация,
  а корректный ответ: база живёт на сервере другой версии.
- **Признак активной версии — только загруженный DLL в свежем процессе.** Уже запущенные
  `1cv8.exe`/`rphost.exe` держат в памяти старый `comcntr.dll` до выхода, реестр на них не влияет.
- **Путь типелиба у 64-битной платформы лежит в `\1.0\0\win64`**, а не в `\win32`.
  Поиск только по `win32` даёт ложное «типелиб не зарегистрирована».
- **Нет типелиба → `Connect()` падает с `TYPE_E_LIBNOTREGISTERED` (0x8002801D)**,
  даже когда CLSID и ProgID правильные. Лечится тем же `regsvr32` из `bin`.

## Расшифровка ошибок check

| Вывод | Что это |
|---|---|
| `ДРУГАЯ ВЕРСИЯ СЕРВЕРА (гейт точный)` | регистрация цела, база на сервере другой версии — нужен `switch` на её версию |
| `не зарегистрирована типелиб` | снесён типелиб — `regsvr32` из `bin` целевой версии |
| `базы нет на сервере` | `Ref` не найден, к регистрации не относится |
| `база есть, нужна учётка` | соединение проходит, не хватает `-UserName`/`-Password` (или `V8_DB_USER`/`V8_DB_PASS` в HKCU) |

Учётку в командную строку из чата не подставляй — пусть скрипт сам берёт `V8_DB_USER`/`V8_DB_PASS`
из HKCU либо переданный `.v8-project.json`.
