# /db-sql-read — чтение таблиц 1С из MS SQL

Работает с базой, у которой в реестре описан `dbms` (`kind = MSSQLServer`). Всё, что нужно
для запроса, видно из самой СУБД; единственное, чего в СУБД нет, — соответствие
«объект метаданных ↔ имя таблицы/колонки», оно берётся из сеанса 1С (см. «Карта хранения»).

## Usage

```
/db-sql-read tables     [database]                                  — семейства таблиц и их число
/db-sql-read find-table [database] -NumberTail 000758               — в каких таблицах этот номер
/db-sql-read find-ref   [database] -Ref 0xAB62…                     — в какой таблице этот _IDRRef
/db-sql-read diff       [database] -Table _DocumentJournal15829 -NumberTail 000758 -NumberTail2 000781
/db-sql-read row        [database] -Table _Document654 -Ref 0xAB50… -Out row.txt
/db-sql-read sql        [database] -Sql "SELECT COUNT(*) FROM _Document667"
/db-sql-read map        [database] -MapFile .1c-db-map.json -Object Документ.ЗаказКлиента
```

## Параметры подключения

Прочитай `.v8-project.json` из корня проекта (скрипт сам идёт вверх от текущей папки) и
разреши базу — алгоритм тот же, что в `/db-list`: по `ref`, `id` или `aliases`.

| Поле записи базы | Куда идёт |
|---|---|
| `dbms.kind` | должен быть `MSSQLServer`, иначе навык базу не берёт |
| `dbms.server`, `dbms.name`, `dbms.user` | сервер, имя БД, пользователь SQL |
| `password` записи **или** `HKCU\Environment\SQL_DB_PASS` | пароль; в вывод не попадает |

Пароль не печатать и не передавать в аргументах `sqlcmd`: в скрипте он уходит в строку
соединения `SqlConnection`, наружу — только `Server / Database / пользователь`.

## Команда

```powershell
powershell.exe -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/db-sql-read.ps1" -Command tables -InfoBaseRef ut11-test
```

| Параметр | Описание |
|---|---|
| `-Command` | `tables` \| `find-table` \| `find-ref` \| `diff` \| `row` \| `sql` \| `map` |
| `-InfoBaseRef` | база в реестре (`ref`/`id`/alias) |
| `-Table` | физическое имя таблицы, например `_Document654` |
| `-Number`, `-Number2` | отображаемые номера (`КАТН-000758`) — если кириллицу можно передать |
| `-NumberTail`, `-NumberTail2` | хвост номера (`000758`) — ASCII-безопасный вариант, скрипт сам достанет полный номер из таблицы |
| `-Ref` | `binary(16)` в hex: `_IDRRef` строки или `_DocumentRRef` из журнала |
| `-Sql` | произвольный запрос; `insert/update/delete/drop/alter/truncate/exec/merge` отклоняются |
| `-MapFile`, `-Object`, `-Field` | карта хранения (см. ниже) и что из неё показать |
| `-Out` | записать вывод в UTF-8 файл (консоль в cp866 кириллицу портит) |

## Раскладка таблиц 1С в MSSQL (замерено на УТ 11, база `ut11-test`)

**Имена таблиц** — технические, кириллицы нет вообще (проверено по `sys.tables`, 8581
таблица, 0 с кириллической первой буквой):

| Семейство | Смысл | Пример |
|---|---|---|
| `_Document<N>` | таблица документов | `_Document531X1` — да, основная таблица `ЗаказКлиента` заканчивается на `X1` |
| `_DocumentJournal<N>` | журнал документов (собранные номера) | `_DocumentJournal15829` |
| `_Reference<N>` | справочники и прочие ссылочные объекты | |
| `_Chrc<N>` | реквизиты документов (дополнительные) | |
| `_InfoRg<N>` / `_AccumRg<N>` (+ `…ChngR`, `…AggDict…`, `…T`, `…St`) | регистры | |
| `_Const<N>`, `_Enum<N>`, `_BPr<N>`, `_Node<N>`, `_ScheduledJobs<N>` | константы, перечисления, бизнес-процессы, узлы, задания | |
| `<таблица>_VT<N>` | виртуальные таблицы (ТЧ, итоги, порядки) — их при поиске исключать можно | `_Document531_VT54066` |
| `<таблица>X1` | **не** «дополнительные реквизиты»: так выглядит основная таблица объекта, если в конфигурации у него есть-extension состояние. Проверено: `Документ.ЗаказКлиента` -> `_Document531X1` | `_Document531X1` |

**Колонки** (замер `evidence/sql_doc_columns.txt`):

| Колонка | Тип | Смысл |
|---|---|---|
| `_IDRRef` | `binary(16)` | PK строки — ссылка на объект |
| `_Version` | `timestamp` | версия строки |
| `_Marked`, `_Posted` | `binary(1)` | помечен для удаления / проведён |
| `_Date_Time`, `_NumberPrefix` | `datetime2` | дата документа / префикс нумерации |
| `_Number` | `varchar` | **сырой** номер, у УТ — с нулевым дополнением: `00000000758` |
| `_Fld<N>` | по типу реквизита | реквизит, `N` — номер хранения |
| `_Fld<N>RRef` | `binary(16)` | ссылочный реквизит |
| `_Fld<N>_TYPE`, `_Fld<N>_RTRef`, `_Fld<N>_RRRef` | `binary(4)`/`binary(16)` | составной тип ссылки: код типа + ссылка |

Ссылка в SQL — это UUID с **переставленными сегментами** (формула из `tools_ui_1c`,
`УИ_ОбщегоНазначения`, `СсылкаВHex`):

```bsl
Сред(УИД, 17, 16) + Сред(УИД, 13, 4) + Сред(УИД, 9, 4) + Лев(УИД, 8)
```

## Карта хранения — единственный источник имён

Внутрь СУБД соответствие «метаданные ↔ таблицы/колонки» не записано: `DBSchema` — один
`varbinary`-блоб, `SchemaStorage` — сериализованные схемы БСП. выдаёт его только сеанс 1С:

```bsl
Структура = ПолучитьСтруктураХраненияБазыДанных(ОбъектыМетаданных, Истина);  // Истина = имена СУБД
// колонки: ИмяТаблицы, ИмяТаблицыХранения, Метаданные, Назначение, Поля, Индексы
// Поля:    ИмяПоля (реквизит)  <->  ИмяПоляХранения (колонка _Fld<N>)
```

Формат кэша (`.1c-db-map.json`, читает `-MapFile`):

```json
{ "objects": [ { "name": "Документ.ЗаказКлиента", "table": "_Document654",
                 "purpose": "основная",
                 "columns": [ { "name": "ПоРезервнойКассе", "column": "_Fld12156",
                                "reference": false } ] } ] }
```

Как получить карту (по возрастанию возни):

1. **Консоль запросов** (внешняя обработка) — выгрузить `Структура.Поля` в CSV/JSON.
2. **Отладчик** — вычислить выражение в приостановленном кадре через MCP-плагин
   `1c-debug`: `eval` с `ПолучитьСтруктуруХраненияБазыДанных(, Истина)` и дальше `.Найти(...)`.
   Два ограничения, оба проверены живьём: парсер выражений отладчика
   **не принимает литералы массива** `[...]` (`Ожидается выражение`), а вызов без
   аргументов считает по всем объектам дольше, чем дефолтные 6 с ожидания события,
   поэтому значение приедет не в ответ инструмента, а в очередь событий.
3. **Внешняя обработка `/Execute`** — если нужен повторимый батч без кликов.

Рабочая формулировка для отладчика (проверено на живом кадре, `evidence/skill_map_verified.txt`):
`ТаблицаЗначений.Найти()` возвращает **строку**, а не таблицу, поэтому дальше идут свойства,
а не `ВыгрузитьКолонку`:

```
ПолучитьСтруктуруХраненияБазыДанных(,Истина).Найти("Документ.ЗаказКлиента","Метаданные").ИмяТаблицыХранения
ПолучитьСтруктуруХраненияБазыДанных(,Истина).Найти("Документ.ЗаказКлиента","Метаданные").Поля.Найти("ПоРезервнойКассе","ИмяПоля").ИмяПоляХранения
```

Вызов без фильтра по объекту строит карту по всем объектам и отвечает не сразу: синхронный
ответ пустой, значение приезжает событием через 15-25 с — ждать его надо в очереди событий,
а не в ответе инструмента. Первый параметр принимает только массив, строку отвергает
(«Ошибка при вызове метода контекста»).

## Грабли окружения (все — сегодняшние замеры)

- **`.ps1` с кириллицей обязан быть UTF-8 *с BOM***. Без BOM PowerShell 5.1 читает файл
  как ANSI, и кириллический литерал доходит до сервера битым (выглядит как ошибка SQL).
  В реестре `.ps1` уже `text eol=lf`, BOM при этом сохраняется.
- **Кириллица не доходит через аргументы** `bash → powershell.exe -File -Param "КАТН…"`:
  для таких вызовов есть `-NumberTail` (ASCII), скрипт сам достанет полный номер из таблицы.
- **`sqlcmd` на этой машине съедает последний символ идентификатора** внутри динамического
  SQL (`Invalid column name '_IDRRe'`), независимо от CRLF/LF и экранирования `[]` —
  поэтому всё через `System.Data.SqlClient`. Не чинить: обход уже выбран.
- **Консоль в cp866** — вывод с кириллицой читать только из файла `-Out`.
- `Write-Output` внутри функции, возвращающей объект, подмешивает строку в результат
  (`$conn` становился строкой и `CreateCommand` падал). Статусные строки — `Write-Host`.

## Известные границы

- Искать документ «на глаз» по номеру нельзя, и нельзя исключать таблицы с суффиксом `X1`:
  у `Документ.ЗаказКлиента` основная таблица — `_Document531X1`, и `_Number` там хранится
  собранным (`РИТН-001600`), а у других документов тот же `_Number` — число с нулевым
  дополнением. Первая же проверка по карте это снимает: `_IDRRef` источника
  `0xAB6200155DE18E0A11F1B41969AF6176` -> `_Document531X1`, `_Fld53030 = 57098.00`,
  и ровно 57098 показал отладчик в памяти (`evidence/skill_map_verified.txt`).
- `_Number` **не уникален**: в УТ один номер встречается у документов разных организаций (замер: `РИТН-001600` — две строки, 4025.08.14 и 4026.09.19). Отбор по номеру обязан идти вместе с `_Date_Time` или с `_IDRRef`, иначе выборка схлопнет разные документы.
- Карта пока не собрана (см. «Как получить карту») — без неё `map` показывает только
  ранее сохранённое.
