# /com-query — запрос к базе через COM-коннектор

Выполняет один запрос от имени учётной записи ИБ и выводит строки результата. Только чтение:
запрос исполняется методом `Execute`, записи в базу не делаются. Рабочий чат-сценарий — «до/после»
при разборе прав, состава данных, счётчиков и связей.

Когда данных больше, чем удобно выгружать запросом (или нужны физические таблицы), ближе `/db-sql-read`.
Смысл этого навыка — там, где нужны метаданные и язык запросов, а не SQL-таблицы.

## Ключевая особенность: имена методов английские

`IDispatch` COM-коннектора 8.5 отдаёт методы по-английски, а кириллические имена (`Выполнить`,
`НовыйОбъект`) в PowerShell **не резолвятся** — `MethodNotFound`. Рабочая форма:

```powershell
$q = $c.NewObject('Query')
$q.Text = 'ВЫБРАТЬ ...'
$q.SetParameter('Имя', $значение)
$sel = $q.Execute().Choose()
while ($sel.Next()) { $sel.Get(0); $sel.Get(1) }
```

У свойства `Наименование.` английские пары: `Text` ← `Текст`, `SetParameter` ← `УстановитьПараметр`,
`Execute` ← `Выполнить`, `Choose`/`Next`/`Get` — у результата. Обратное неверно: кириллица объектов
(свойства справочников и т.п.) работает как обычно. `Columns` у результата пуст — имена колонок не
отдаются, вывод позиционный.

Закрывать соединение нечем: `Disconnect`/`Close` не резолвятся, сеанс умирает с процессом.

## Параметры подключения

База — из `.v8-project.json` вверх от текущей папки (тот же резолвер, что у `/access-profiles`):
по `id` / `ref` / `name` / алиасу. Прямо: `-InfoBaseServer` + `-InfoBaseRef` или `-InfoBasePath`.
Учётка ИБ: `-UserName`/`-Password`, иначе `HKCU\Environment\V8_DB_USER` / `V8_DB_PASS`.
В вывод пароль не попадает.

## Команда

```powershell
powershell.exe -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/com-query.ps1" -Sql "<запрос>" -InfoBaseRef <база> -OutFile <файл.txt>
```

| Параметр | Описание |
|---|---|
| `-Sql` | Текст запроса. Альтернатива — `-SqlFile <файл>` (удобно для многострочных) |
| `-Param` | Параметр строкой `Имя=значение`; повторяемый |
| `-ParamInt` | Параметр числом `Имя=число`; повторяемый |
| `-MaxRows` | Предел выводимых строк, по умолчанию 1000 |
| `-InfoBaseRef` | База из реестра: `id`, `ref`, `name` или алиас |
| `-InfoBaseServer`, `-InfoBasePath` | Соединение мимо реестра |
| `-UserName`, `-Password` | Учётка базы |
| `-ProgId` | Переопределить ProgID коннектора |
| `-OutFile` | Отчёт в UTF-8-файл; без него вывод идёт в консоль, где кириллица ломается |
| `-Separator` | Разделитель полей, по умолчанию ` \| ` |

## Грабли языка запросов (проверено на УТ)

- Строковый литерал — **двойные** кавычки и ровно по одной с каждой стороны: `ПОДОБНО "%Иванов%"`.
  Апострофы и удвоенные кавычки по краям парсер не принимает.
- Алиас таблицы `В` конфликтует с ключевым словом `В` (условие-подзапрос) — «Ожидается имя».
  Берите `ВД`.
- `ССЫЛКА Справочник.Х` как проверка типа не поддерживается — «Неизвестный тип». Оборачивайте
  `ВЫРАЗИТЬ(Поле КАК Справочник.Х) <> НЕОПРЕДЕЛЕНО`.
- `ПУСТАЯССЫЛКА` не функция — `ЗНАЧЕНИЕ(Справочник.Х.ПустаяСсылка)`.
- Ссылка из результата, переданная параметром, у многих типов даёт `0` строк в сравнении
  `Поле = &П`. Надёжнее соединять по реквизиту-представлению (Наименование) или сравнивать
  через `ВЫРАЗИТЬ`.
- Обращение к табличной части чужого алиаса из внешнего запроса (`П2.Пользователь.Наименование`)
  не резолвится — отдельный запрос по ТЧ с соединением.
- Составной тип (`ГруппыДоступа.ВидыДоступа.ВидДоступа`) точкой к `Наименование` не читается:
  только `ВЫРАЗИТЬ`.

## Приёмы

- Многострочный запрос — файлом (`-SqlFile`), чтобы не ломать кавычки в командной строке.
- `РАЗРЕШЕННЫЕ` в тексте — результат считается с RLS текущего пользователя.
- Вывод — позиционно по числу полей выборки; `-MaxRows` защищает от гигантских ТЗ.
- Пустой результат не ошибка: навык печатает `строк: 0`.

## Ограничения

- Нет учётки — подключение не выполнится; creds берутся только из HKCU или аргументов.
- COM-коннектор должен быть зарегистрирован той же ветки, что база (иначе «Несовпадение версий»),
  см. `/com-client-switch`.
- Пакеты запросов (`ВыполнитьПакет`) не поддерживаются — только один запрос.
