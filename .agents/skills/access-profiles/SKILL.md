# /access-profiles — профили групп доступа и их роли

Отвечает на вопросы «каким профилям назначена роль X» и «какие роли в профиле Y».
Состав профилей — это **данные** информационной базы, а не метаданные: в XML-выгрузке
конфигурации и расширений его нет, `role-info`/`cfe-diff` его не покажут.

Команды:

| Команда | Что выдаёт |
|---|---|
| `profiles` | профили, в ТЧ «Роли» которых есть указанная роль (`-Role`) |
| `roles` | роли, входящие в профиль (`-Profile`) |
| `list` | все пары «профиль \| роль», можно сузить `-Role` и `-Profile` |

## Usage

```
/access-profiles profiles -Role БазовыеПраваБСП -InfoBaseRef demo-base
/access-profiles roles    -Profile БухгалтерОсновной -InfoBaseRef demo-base
/access-profiles list     -InfoBaseRef demo-base -Profile "*номенклатур*"
/access-profiles profiles -Role МоеРасширение_БазовыеПраваБСП -InfoBaseRef demo-base -NoCom   # только SQL-путь
```

## Параметры подключения

Прочитай `.v8-project.json` (скрипт сам идёт вверх от текущей папки) и разреши базу по
`id` / `ref` / `name` / `aliases`. Программный ID COM-коннектора берётся из версии
платформы в `v8path` (`8.5.x` → `V85.COMConnector`, `8.3.x` → `V83.COMConnector`).

Пользователь и пароль: `-UserName`/`-Password`, иначе `HKCU\Environment\V8_DB_USER` /
`V8_DB_PASS`. В вывод пароль не попадает.

## Команда

```powershell
powershell.exe -NoProfile -File ".agents/skills/access-profiles/scripts/access-profiles.ps1" <Command> -InfoBaseRef <база> -OutFile <файл.txt>
```

| Параметр | Описание |
|---|---|
| `-Command` | `profiles` \| `roles` \| `list` (позиция 0) |
| `-Role` | роль для `profiles`/`list`: подстрока или маска `*`/`?` |
| `-Profile` | профиль для `roles`/`list`: подстрока или маска `*`/`?` |
| `-InfoBaseRef` | база из реестра: `id`, `ref`, `name` или алиас |
| `-InfoBaseServer`, `-InfoBasePath` | соединение мимо реестра (серверная / файловая база) |
| `-UserName`, `-Password` | учётка базы |
| `-ProgId` | переопределить ProgID коннектора (например `V83.COMConnector`) |
| `-NoCom` | не пробовать COM, читать сразу из СУБД |
| `-IncludeMarked` | включить профили, помеченные на удаление (по умолчанию пропускаются) |
| `-Exact` | роль сравнивать точно (`-eq`), а не как подстроку: имена ролей — префиксы друг друга (`ДобавлениеИзменениеНоменклатуры` и `…НоменклатурыПартнеров`) |
| `-OutFile` | записать отчёт в UTF-8-файл. Без него вывод идёт в консоль, где кириллица ломается |

## Два источника данных

Скрипт сначала пробует **COM-соединение 1С**, а если коннектор не зарегистрирован или
подключиться не удалось — читает **напрямую из MS SQL** (когда у базы в `.v8-project.json`
есть `dbms.kind = MSSQLServer`). `-NoCom` форсирует SQL-путь. Первая строка отчёта
показывает, каким путём получены данные: `источник: COM (V85.COMConnector)` или
`источник: SQL localhost/demo-base`.

Оба пути дают одинаковый результат (сверено на `demo-base`: 7441 пара, 949 ролей у
«БухгалтерОсновной», 40 профилей у `БазовыеПраваБСП` — совпадение построчно).

Прямое чтение работает через `System.Data.SqlClient`; реквизиты — из `dbms`-блока записи
базы, пароль — оттуда же либо `SQL_DB_PASS` (пользовательские переменные). Параметры
передаются как `SqlParameter`, поэтому кириллица не страдает от кодовой страницы консоли.
Поддерживается только MS SQL.

## Как это устроено в базе (не проходить заново)

- Хранение: `Справочник.ПрофилиГруппДоступа`, ТЧ **«Роли»**; ссылка на профиль — `Р.Ссылка`.
- **Роль в ТЧ — составная ссылка** двух видов: `Справочник.ИдентификаторыОбъектовМетаданных`
  (роли конфигурации) и `Справочник.ИдентификаторыОбъектовРасширений` (роли расширений).
  Поэтому ответ «кто использует роль расширения» находится тем же запросом.
- В идентификаторе **`Имя` = имя метаданных** (`БазовыеПраваБСП`), а **`Наименование` = синоним**
  (`Базовые права БСП (Роль)`). Искать нужно по обоим — скрипт так и делает.
- ⚠ **Составную ссылку нельзя сравнивать с однотипной в условии соединения**:
  `ПО Р.Роль = И.Ссылка` платформа отвергает (в COM это выглядит как
  `Object reference not set to an instance of an object`). Вместо join — обращение через точку:
  `Р.Роль.Имя`, `Р.Роль.Наименование` — общие реквизиты обоих типов резолвятся.
- Профили — данные, поэтому их правка проверяется только перечитыванием базы,
  а не выгрузкой XML.

Рабочий запрос (его и выполняет скрипт):

```sql
ВЫБРАТЬ
	П.Наименование КАК Profile,
	П.ПометкаУдаления КАК Marked,
	Р.Роль.Имя КАК RoleName,
	Р.Роль.Наименование КАК RoleSynonym
ИЗ
	Справочник.ПрофилиГруппДоступа.Роли КАК Р
	ВНУТРЕННЕЕ СОЕДИНЕНИЕ Справочник.ПрофилиГруппДоступа КАК П
		ПО Р.Ссылка = П.Ссылка
УПОРЯДОЧИТЬ ПО
	Profile, RoleName
```

## Путь 1: COM-коннектор 1С

Нужен **зарегистрированный COM-коннектор той же ветки платформы**, что и база
(8.3-коннектор к 8.5-базе не подключится: «Несовместимость версии конфигурации и версии
1С:Предприятие»).

Регистрация `comcntr.dll` (от администратора), **рабочий каталог обязателен**:

```powershell
Start-Process regsvr32 -ArgumentList '/s','comcntr.dll' `
  -WorkingDirectory 'C:\Program Files\1cv8\<версия>\bin' -Wait
```

Без `-WorkingDirectory` regsvr32 возвращает код 3: `comcntr.dll` зависит от `core<NN>.dll` и
`nuke<NN>.dll` из того же каталога, а по полному пути зависимостями не ищутся. Проверка:

```powershell
(New-Object -ComObject 'V85.COMConnector') | Out-Null   # без исключения = зарегистрирован
```

Через COM берётся тот же запрос (см. выше). Если коннектор не встал — падать не нужно:
скрипт сам уйдёт на SQL-путь, если у базы есть `dbms`-блок.

## Путь 2: напрямую из MS SQL

Номера таблиц в 1С-базе (`_Reference347_VT34626`, `_Reference170X1`, …) **не переносятся
между базами и версиями конфигурации** — их нельзя хардкодить. Скрипт находит всё по данным:

1. **Таблицы идентификаторов** — справочники табличного вида, где есть строки
   `_Description LIKE '%(Роль)'` («Базовые права БСП (Роль)»). Обычно их две:
   `ИдентификаторыОбъектовМетаданных` и `ИдентификаторыОбъектовРасширений`.
2. **Таблица профилей** — та ТЧ (`_ReferenceNNN_VTMMM`), составная ссылка которой
   (`_Fld…_RRRef`) чаще всего указывает именно на **роли**. Прочие таблицы тоже ссылаются
   на идентификаторы (объекты, отчёты), поэтому выбирается максимум по числу совпавших
   ролей, а не первое попадание.
3. **Колонка имени метаданных** — в идентификаторе `_Description` это синоним, а имя
   (`БазовыеПраваБСП`) лежит в отдельном реквизите. Он находится структурно: значение
   является суффиксом реквизита «ПолноеИмя» (`Роль.БазовыеПраваБСП`).
4. **Колонка владельца ТЧ** — `_ReferenceNNN_IDRRef` в таблице ТЧ; имя родительской
   таблицы — префикс до `_VT`.

Ограничения SQL-пути: только MS SQL (для PostgreSQL нет `sys.tables`/`sys.partitions`),
нужен `dbms`-блок в `.v8-project.json`; обнаружение схемы занимает несколько секунд
(сканирование справочников на строки `(Роль)`), на большой базе — до минуты.

Ещё одна ловушка .NET: `DataTable` — `IEnumerable`, и `return $dt` из функции PowerShell
разворачивает его в массив `DataRow`; нужна запятая — `return ,$dt`.

## Чтение результата

Всегда передавай `-OutFile` и читай файл инструментом Read: консоль в cp866 портит кириллицу.
При работе через PowerShell COM-выборка отдаёт значения только позиционно (`Get(0)`, `Get(1)`) —
именованные поля вроде `$sel.RoleName` резолвятся в пустую строку; скрипт это уже учитывает.
